## Why

当前移动端工作台把服务启动、地址、二维码、共享文件、项目内容和设置入口集中在同一屏，用户第一次进入时需要自己判断下一步该做什么；同时部分按钮和容器仍显得信息密度失衡，降低了 FileFlash-Bridge 作为跨平台工具的可信度。

本次变更希望把首页从“功能堆叠面板”调整为“分步引导式工作流”：用户先启动服务，再进入统一的内容与共享工作区，在同一处处理别人发送的文件、App 导入内容、项目查看、加入共享、导出保存等协同操作，同时用更克制、更高级的视觉层级和图标化操作减少廉价感与文字负担。

## What Changes

- 将首页工作台重构为分步模式，按 `1 启动服务 -> 2 内容与共享工作区` 的顺序组织核心功能。
- 将共享/导入、别人发送的文件、项目内容查看和共享状态管理合并在同一个内容工作区中，不拆成互相隔离的步骤。
- 首屏优先展示当前步骤、下一步动作和必要状态，避免同时暴露所有功能区造成认知负担。
- 将常用操作按钮尽量图标化，例如复制链接、刷新地址、导入文件、导入媒体、选择下载、更多菜单、帮助入口；保留必要的可访问名称和少量关键文案。
- 改善视觉质感：使用更稳定的空间层级、克制色彩、轻量表面、明确焦点态和一致图标语言，避免卡片堆叠、重复大按钮和廉价装饰。
- 保持首页与设置页、底部 Tab、引导浮层的视觉系统一致，避免出现互相脱节的组件风格。
- 保留现有传输能力、项目管理、文件导入/导出、共享列表、语言设置、安全模式和浏览器门户行为，不新增或修改局域网传输协议。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `workspace-visual-refresh`: 增加移动端工作台必须以分步式主流程呈现，并要求内容查看、文件导入和共享操作在同一工作区协同完成，同时减少同屏功能堆叠、优先使用图标化操作并提升整体视觉质感。

## Impact

- 影响移动端 React Native 共享代码，主要包括 `AppShell`、`HomeScreen`、`SettingsScreen`、`appShellStyles`、共享 UI 包装组件和图标组件。
- iOS 与 Android 必须共享相同的信息架构、步骤语义和核心交互；平台差异仅允许出现在安全区、系统返回、触感反馈或系统文件选择器等原生行为上。
- 不需要引入新的第三方原生库或自定义 Native Module；优先复用 React Native Paper、现有图标组件、现有本地存储和服务状态模型。
- 不改变本地传输服务、HTTP API、二维码内容、文件系统权限模型或浏览器门户协议，因此安全、隐私和兼容性边界保持不变。
- 验证范围包括移动端布局快照/组件测试、iOS/Android 常见屏宽手动检查、步骤状态切换、图标按钮可访问标签、服务启停、内容与共享工作区、收到文件后加入共享、文件导入和项目内容展示回归。
