## Context

FileFlash-Bridge 当前首页已经具备服务启停、地址/二维码、共享文件、项目内容、项目历史、语言切换和新手引导等能力，但这些能力在同一工作台中同时出现，用户需要自己理解“先启动服务，再处理内容与共享”的主路径。现有实现主要位于 React Native 共享层，iOS 与 Android 复用同一套 `AppShell`、`HomeScreen`、`SettingsScreen`、`useAppModel` 和样式 token。

本次设计只调整移动端 App 的信息架构、视觉层级和操作呈现，不改变本地传输服务、HTTP API、二维码、文件存储、权限申请或浏览器门户协议。文件上传、文本提交、文件导出/保存、共享列表下载和异常反馈继续走现有模型，并在“内容与共享工作区”中协同呈现，避免把收到的文件、导入文件、项目查看和共享操作拆散。

## Goals / Non-Goals

**Goals:**

- 将首页主路径调整为清晰的两段式工作流：启动服务、内容与共享工作区。
- 在同一个内容与共享工作区中承载别人发送的文件、App 导入内容、项目内容查看、加入/移出共享、导出保存和批量下载。
- 让当前最重要的下一步操作在首屏显著可见，降低第一次使用时的判断成本。
- 将复制、刷新、导入、选择、更多、帮助等重复操作改为图标优先的按钮，同时保留可访问标签。
- 建立更高级、更克制的视觉层级，减少大面积文字、重复卡片和同屏功能堆叠。
- 保持 iOS 与 Android 共享实现一致，仅允许安全区、系统返回、系统文件选择器和触感反馈存在平台差异。

**Non-Goals:**

- 不新增传输协议、服务端 API、二维码字段或浏览器门户能力。
- 不改变文件上传、文本提交、共享文件下载、导出保存、安全模式和语言设置的业务语义。
- 不引入新的第三方原生库或自定义 Native Module。
- 不把首页拆成新的一级 Tab；设置页仍承载应用级偏好，首页仍承载传输工作流。

## Decisions

1. **步骤状态从现有模型派生，而不是新增持久化状态**

   UI 可根据 `serviceState.phase`、`serviceState.accessUrl` 和 `serviceState.network.reachable` 判断用户是否仍处于“启动服务”阶段；服务可达后进入统一的“内容与共享工作区”。`sharedFiles.length`、`activeProject` 和 `activeProjectFiles/messages` 只用于决定该工作区内部显示哪些内容摘要、列表和操作，而不再推导成单独的后续步骤。这样可以避免新增迁移和状态同步问题，也能让刷新、恢复前台、导入文件、浏览器上传和服务状态变化自然更新 UI。

   备选方案是新增 `currentWorkspaceStep` 并持久化，或把共享与项目内容拆成两个步骤；前者会产生“用户上次停在内容步骤但服务已经停止”的矛盾状态，后者会割裂“收到文件后继续加入共享/导出/查看项目”的真实流程，因此都不采用。

2. **首页保留一个工作流页面，但按服务与内容两个阶段渐进展开**

   首页仍是传输工作台，不新增多页路由。服务未就绪时聚焦启动服务；服务就绪后服务区域压缩为摘要，内容与共享工作区成为主区域。该工作区内部可以用分段、列表、摘要或局部折叠组织收到的文件、共享列表和项目内容，但这些内容必须处于同一工作上下文中，方便用户把别人发送的文件继续加入共享、导出或查看所属项目。

   备选方案是拆成多个页面、Tab 或独立步骤，但会增加跨区域跳转成本，并削弱“局域网投递工作台”的连续性。

3. **图标优先但不牺牲可访问性**

   高频操作优先使用现有图标组件或 React Native Paper 图标按钮：复制链接、刷新地址、导入文件、导入媒体、加入/移出共享、选择下载、清空选择、更多菜单、语言切换和帮助入口。每个图标按钮必须提供 `accessibilityLabel`、稳定 `testID`，必要时保留短标签或状态文本，避免纯图标造成误用。

   备选方案是完全移除文字按钮，但启动服务、停止服务、下载选中、危险确认等关键动作仍需要明确语义，因此保留短文案。

4. **视觉升级基于现有主题 token 和 Paper 体系**

   继续使用 React Native Paper、`theme` token、`PanelSurface`、`GlyphIconButton` 等共享组件。新增样式应强化留白、层级、焦点态和中性色基底，避免另起一套颜色系统或装饰性背景。

   备选方案是引入新的图标库或动效库，但当前需求可以通过已有组件和样式系统完成，引入依赖会增加 iOS/Android 包体和兼容风险。

5. **传输、保存、文本和异常流程保持原实现，只调整入口位置**

   浏览器文件上传仍由本地服务接收并写入 App 内会话存储；文本提交仍进入当前项目；App 内文件导出仍调用现有平台文件保存/分享路径；上传、保存、网络不可达、权限缺失、空间不足等异常仍通过现有 notice/banner 和错误消息反馈。步骤 UI 只负责把这些入口放到“服务摘要”和“内容与共享工作区”的正确上下文中。

## Risks / Trade-offs

- **风险：图标化后用户看不懂按钮含义** → 对关键操作保留短标签或上下文标题，并为所有图标按钮提供可访问名称和测试覆盖。
- **风险：内容与共享工作区过大导致首屏再次拥挤** → 只压缩服务阶段和辅助信息，内容区内部使用分段摘要、列表密度和上下文工具栏组织信息，不把项目查看和共享操作拆到不同步骤。
- **风险：首屏视觉更克制后状态反馈不够显眼** → 服务不可达、导出失败、上传失败、权限缺失等阻断状态继续使用统一反馈组件，并在当前步骤附近呈现。
- **风险：iOS/Android 安全区和系统返回表现不一致** → 布局继续使用 SafeArea，Android 返回键在引导或抽屉打开时优先关闭当前浮层，核心步骤状态保持共享逻辑。
- **风险：仅重组 UI 可能遗漏现有功能入口** → 任务中必须建立功能清单回归，覆盖服务启停、复制/刷新地址、文件/媒体导入、批量下载、项目切换、重命名、删除、消息复制和文件导出。

## Migration Plan

1. 先在共享 React Native 层引入“启动服务 / 内容与共享工作区”的派生模型和配置，不改变 `useAppModel` 的业务方法签名。
2. 重构 `HomeScreen` 布局为服务步骤、服务摘要和统一内容与共享工作区，并保留现有测试 ID 的兼容映射或新增稳定测试 ID。
3. 将高频文字按钮替换/包装为图标优先按钮，补齐 `accessibilityLabel`。
4. 更新样式 token 和共享 UI 组件，统一 Home、Settings、Tab、Onboarding 的视觉层级。
5. 回归 iOS/Android 常见屏宽、服务启停、文件导入/导出、文本项目、共享文件和错误反馈。
6. 若发布后发现步骤 UI 阻碍高级用户，可通过恢复完整展开布局或保留“展开全部”入口回滚体验层，不需要回滚传输能力。

## Open Questions

- 是否需要为高级用户提供内容与共享工作区的“展开全部”或“紧凑模式”入口，还是首版只提供默认分段布局？
- 图标资源是否完全复用现有 `AppIcons`，还是需要补充少量自绘/平台图标来覆盖导入媒体、选择模式和帮助入口？
