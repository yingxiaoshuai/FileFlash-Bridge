## Context

FileFlash-Bridge 首页当前同时展示服务控制、共享文件和当前项目内容。虽然功能完整，但服务未启动时，用户会看到多个并列区块和空态，容易把“启动局域网服务”“添加共享文件”“查看项目内容”的先后关系理解成同等入口。本次变更需要把首页改为更明确的步骤式工作流：未启动时以中心大圆形按钮作为第一步，启动后再显示访问地址、二维码、共享文件和项目内容。这个首页仍然必须是可直接使用的功能界面，而不是使用说明页或静态教程页。

现有实现已经具备 React Native Paper 风格组件、服务状态模型、共享文件列表、项目历史、当前项目内容、浏览器门户、设置页语言入口和新手引导锚点。本设计优先复用这些共享层能力，不调整本地传输服务接口、文件桥、上传/下载协议或持久化结构。

## Goals / Non-Goals

**Goals:**

- 在 iOS 与 Android 共享首页中建立“启动服务 → 共享文件 → 项目内容”的步骤式信息架构。
- 服务未启动、启动中、运行中、错误态都能用清晰视觉状态和用户提示表达。
- 未启动状态下，将启动服务改为首页中心的大圆形主操作，并保留安全模式、网络状态和必要错误提示。
- 服务运行后，展示访问地址、二维码、复制链接、刷新地址、停止服务、共享文件和当前项目内容。
- 首页每一步都必须承载真实业务操作，不把首屏做成使用说明或纯引导内容。
- 语言切换入口显示另一个可切换目标语言：中文界面显示 `English`，英文界面显示 `中文`。
- 文件上传、文件保存/导出、文本提交和共享下载继续沿用现有服务与门户链路，且在 UI 中保持可理解的反馈。
- 首页视觉提升继续基于 React Native Paper 语义、现有 theme token 和共享组件完成。

**Non-Goals:**

- 不新增云传输、外网中继、账号体系或跨设备发现能力。
- 不改变浏览器门户的 API、上传分片、共享下载、文本提交、二维码或安全模式协议。
- 不改变入站文件保存位置，不把上传成功等同于写入系统公共目录。
- 不新增第三方原生库或自定义 Native Module。
- 不移除项目历史、当前项目管理、共享文件下载/保存等既有能力。
- 不新增独立的“使用说明首页”、教程页或需要用户读完说明才能继续的流程。

## Decisions

1. **首页用服务状态驱动分步展开。**

   决策：在 `HomeScreen` 中根据 `serviceState.phase` 和 `hasReachableAddress` 派生首页阶段。`idle`、`stopped`、`error` 进入“启动步骤”视图；`starting` 显示同一大圆形入口的忙碌态；`running` 且地址可达时展开完整共享工作台。阶段切换只控制真实功能区域的可见性和主次关系，不新增静态说明页。

   理由：现有服务状态已经是工作台核心状态源，复用它可以避免新增路由或独立向导状态，也能保证 iOS 与 Android 行为一致。

   备选：新增独立 onboarding 式多页流程。该方案会增加状态同步复杂度，也容易让老用户多一步操作，因此不采用。

2. **中心大圆形启动入口只替代服务主按钮，不替代服务能力。**

   决策：未启动状态下，启动/重试服务以居中大圆形按钮呈现；安全模式开关、网络标签、错误提示和帮助入口保留在按钮附近的辅助区。运行状态下，停止服务可以回到紧凑按钮或状态区操作，不强制继续占用大圆形形态。

   理由：用户明确要求“启动服务改为中心的一个大圆圈”，其目的是突出第一步。运行后用户的主要任务转向地址扫码、共享文件和项目内容，继续让大圆按钮占据中心会浪费空间。

   备选：任何状态都使用大圆按钮。该方案会弱化运行后的地址与二维码，不利于局域网访问，因此不采用。

3. **服务运行前折叠共享文件和项目内容，运行后展开。**

   决策：服务未运行时，首页不再完整渲染共享文件列表和项目内容列表，只展示下一步预告或轻量摘要；服务运行且有可达地址后，再显示共享文件区和当前项目区。已有数据不被清空，用户启动服务后立即看到原有共享和项目内容。

   理由：这能把首屏焦点交给启动服务，同时保留数据连续性。共享列表和项目内容本身仍属于当前会话，不需要迁移数据模型。

   备选：保留所有区域但调低视觉权重。该方案仍会让页面看起来拥挤，不能解决“不是按步骤使用”的核心问题。

4. **文件上传、文件保存、文本提交流程保持协议不变，只调整入口上下文和提示。**

   决策：浏览器上传文件、提交文本和下载手机共享文件仍由门户页调用现有 HTTP 接口；App 内文件保存/导出仍使用现有显式导出流程。首页只负责更清晰地告诉用户服务启动后才能让浏览器访问，并在运行后显示共享文件与项目内容。

   理由：用户需求是工作台使用步骤和美观度，不是传输能力重写。保留协议能降低 iOS、Android 和 Harmony 回归风险。

   备选：把共享文件选择、上传、文本提交做成 App 内完整向导。该方案会混淆浏览器投递模型，并扩大实现范围，因此不采用。

5. **异常处理和重试在同一主步骤内完成。**

   决策：启动失败、网络不可达、权限缺失或端口绑定失败时，大圆形入口显示可重试语义，辅助区展示失败原因和恢复动作。不会展开共享文件和项目内容以避免误导用户认为服务可用。

   理由：局域网服务不可用时，后续浏览器访问无法成立；将错误反馈放在第一步能减少用户在后续区域里寻找原因。

   备选：启动失败后仍展示完整工作台。该方案容易让用户继续操作无效共享入口，因此不采用。

6. **新手引导锚点跟随新步骤结构调整。**

   决策：`service-panel` 继续指向新的启动中心；`service-address` 只在服务运行且地址可达时高亮；`shared-files-panel` 和 `project-panel` 在运行状态下参与引导。若用户首次进入时服务未启动，引导文案聚焦“先启动服务”。

   理由：引导应该解释真实可见的控件，而不是遮罩不存在或折叠的区域。

   备选：保留旧锚点但让遮罩找不到目标时跳过。该方案会造成引导步骤不稳定，因此不采用。

7. **语言切换入口显示目标语言，而不是当前语言说明。**

   决策：设置页或首页中已有的语言切换入口，在中文界面下显示 `English`，在英文界面下显示 `中文`。如果仍保留语言菜单，菜单可以继续包含两种语言；但默认可见入口必须突出另一个目标语言，而不是显示“当前语言：中文”这类对中文用户帮助不大的信息。

   理由：中文用户通常不需要切换语言；真正会点击语言入口的是想切到英文的用户，因此直接显示 `English` 更符合意图。英文界面同理，显示 `中文` 能让想切回中文的用户快速找到目标。

   备选：始终显示当前语言名称。该方案会让中文界面出现“中文”这类低价值信息，用户很难判断点击后是否能切换到英文，因此不采用。

## Risks / Trade-offs

- [Risk] 老用户习惯在未启动服务时先整理共享文件，折叠列表可能增加一步操作。→ Mitigation：未启动态保留共享文件数量和“启动后继续管理”的预告，运行后原列表立即展开；如实现中保留添加入口，必须明确其不会暴露给浏览器直到服务启动。
- [Risk] 大圆形按钮在小屏上可能挤压安全模式和网络提示。→ Mitigation：为圆形入口设置响应式直径、最大/最小尺寸和固定纵向间距，辅助信息以紧凑行或折叠提示呈现。
- [Risk] 启动中状态如果缺少反馈，会被误认为卡住。→ Mitigation：大圆形入口必须有 disabled/busy 视觉、状态文案和必要的系统反馈；失败后恢复为可重试。
- [Risk] 服务运行后才展开内容可能影响自动化测试的元素查找。→ Mitigation：更新测试以先启动或模拟 running 状态，再断言共享文件和项目内容；对未启动态新增专门断言。
- [Risk] 视觉升级可能偏离现有 Paper 主题。→ Mitigation：新增样式只使用现有 `theme` token 和共享组件语义，不引入第二套颜色和控件体系。
- [Risk] 分步骤首页如果写太多说明文案，会变成教程页而不是工具页。→ Mitigation：每个阶段只保留必要状态和操作文案，主屏始终以可点击业务动作和真实数据为核心。
- [Risk] 语言入口只显示目标语言后，当前语言状态不如以前直观。→ Mitigation：设置页语言详情或菜单中仍可展示当前选中状态，但默认入口优先显示可切换目标。

## Migration Plan

1. 在 `HomeScreen` 中派生首页阶段，重组服务控制区、共享文件区和项目区的渲染条件。
2. 新增或调整共享 UI 片段：中心启动区、步骤提示、运行后地址/二维码区、未运行摘要/预告区。
3. 更新 `appShellStyles`，为大圆形入口、步骤区块、运行后展开区域和小屏布局补齐响应式样式。
4. 更新 i18n 文案，覆盖启动第一步、启动中、启动失败重试、启动后共享文件和项目内容提示，并避免把首页写成使用说明。
5. 调整新手引导文案与锚点测量，确保未启动和运行状态都不会高亮不可见目标。
6. 调整语言切换入口，使中文界面默认显示 `English`，英文界面默认显示 `中文`，并保留可恢复语言选择的状态。
7. 验证 iOS、Android 和可用的 Harmony 构建：启动服务、复制链接、扫码/浏览器访问、上传文件、提交文本、下载共享文件、导出保存、停止服务、语言切换和错误重试。

Rollback 策略：由于不改变数据模型和传输协议，若新布局出现严重问题，可回退 `HomeScreen`、样式和文案到旧的同屏布局；已有会话、共享文件、项目和服务配置不需要迁移。

## Open Questions

- 未启动态是否允许直接“添加共享文件/图库”，还是严格要求启动服务后才展示添加入口？默认按用户描述采用严格步骤：启动后再显示共享文件区。
- 运行后是否仍保留大圆形停止按钮，还是改为紧凑停止入口？默认采用紧凑停止入口，把首屏空间让给地址、二维码和共享内容。
